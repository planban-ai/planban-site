# Planban v1.1.7

Planban v1.1.7, released on 11 October 2026, stops the board page reloading in a loop, shows which cards are waiting on you, helps agents keep cards up to date, and makes the install smaller with a clean security audit.

## What was fixed on the board page?

The board page no longer reloads several times a second. Opening a board recorded the time it was opened, and that write woke the board's file watcher, which reloaded the page and started the cycle again. The open time is now recorded at most once a minute, and the watcher ignores the temporary lock folder that every board read creates. Real card and document edits still reach the page.

## How do I see which cards need me?

An In Progress or Up Next card shows **Needs you** when its next action starts with `Owner:`. Agents are now asked to start a next action with `Owner:` only when the next step is yours. See [Specs, Plans and next actions](/docs/specs-plans-next-actions/).

## What are out-of-date warnings?

Agents now see a warning on an In Progress or Up Next card when:

- a pull request the card mentions merged after the card last changed;
- its Spec or Plan was edited outside Planban;
- it has been In Progress with no update for five days;
- a Group's Items changed more than a day after the Group did; or
- its next action is waiting on you.

`planban_get_card` and `planban_query_cards` return these signals for each card, and `planban_status` and `planban_get_board` return a short list of cards that need attention, plus the number of Items In Progress when it is over 12. The warnings are best-effort and read only local git and board history. Planban never fetches from a remote to work them out.

Agents are asked to fix out-of-date cards they own or touch in the same batch of changes, to keep preview links, branch and session names, commit IDs and merge or deploy state out of the summary and next action unless the Item owns that environment, and to update the In Progress Items that name work when it lands. Creating or updating a card adds a gentle note when an Item's details grow past about 4 KB.

## What changed in Copy Reference?

Copy Reference puts one short line on the clipboard: the card title in quotes, followed by an exact reference, `planban:<board>/<item>`. The button shows a tick to confirm the copy. Agents in every host are told to look the reference up with `planban_get_card` and to trust the ID over the title.

In Claude Code, the session-start hook names the exact agent-context file to read, including from a linked git worktree, where the file lives in the main checkout. It also adds one line naming cards that are out of date.

## Is the install smaller?

Yes. First-run set-up no longer installs Cloudflare's Wrangler, Miniflare, workerd and sharp, which nothing in Planban used. That removes 61 packages from every install. The dependencies that remain are updated to clear the high-severity security audit.

## What else changed?

- Board history now prunes as intended. Planban keeps the newest board versions, then one per hour for two days and one per day up to the retention limit. A large backlog clears gradually, at most 500 versions per board write.
- The README, support, contributing and security guides are written for every supported host, with the right feedback command for Codex and Claude Code.

## How do I update to v1.1.7?

This release changes dependencies, so updating from v1.1.6 runs a clean dependency installation. Refresh the marketplace and reinstall the plugin so the cached skills, hook scripts and MCP instructions update, then start a new session. Existing boards keep their storage format, so no migration is needed. See [Update Planban](/docs/updating/) for the commands in each host.

To pick up the new generated guidance in an existing project, [run set-up again](/docs/set-up-a-project/#how-do-i-refresh-a-projects-generated-guidance-after-an-update) with the project's board id.
